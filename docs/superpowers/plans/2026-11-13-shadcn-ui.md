# React + shadcn/ui migration

User choice: directly rewrite all pages with React and official shadcn/ui.

## Constraints and design
- Keep Express endpoints, authentication, portfolio JSON, backups and NAV fixes compatible.
- Use official generated shadcn/ui components, React, Vite, Tailwind, and existing ECharts.
- Neutral white/zinc surfaces, dark primary actions, red gains/green losses, tabular numbers.
- Top navigation for holdings, performance, allocation and import/export; responsive overflow for financial tables.
- Preserve group CRUD/reordering, fund search/add/edit/delete/move, account identity, targets, PDF preview/apply, plugin import/export, backups and settings.
- Do not mutate personal holdings while testing. No publication or remote push.

## Tasks
1. Configure React/Tailwind/shadcn and official components; retain existing calc.js and api.js.
2. Rewrite app/session/refresh shell, login, settings and holdings; validate failed saves and refresh races.
3. Rewrite performance, allocation and all import/export flows; preserve confirmations and preview details.
4. Remove unused Vue/Element Plus source/dependencies; run backend and frontend behavior tests and build.
5. Check real rendered UI at desktop and mobile widths, navigation, dialogs and errors; independent final review.

## Review focus
- Never overwrite unsaved edits or close forms on failed persistence.
- Ignore late requests after logout/range or account changes.
- Empty holdings, unavailable quotes, missing cost and zero targets remain representable.
- Imports retain full preview and require explicit confirmation before replacing data.
- Browser QA uses read-only operations; mutation tests use fixtures.
